Open source · TypeScript

An AI teammate that asks before it acts.

scriptorium works in Slack, Jira, Confluence and GitHub. It answers with sources or says it doesn't know, proposes tickets, pages and edits, and changes nothing until a named person approves the exact change.

What it does

One engine and one policy layer run every agent. The Teammate is the general one: it reads widely inside its allow-lists, and each write it proposes waits on a card for a listed approver.

How it stays safe

A rule that only lives in a prompt holds as well as the model obeys it. Here each rule is enforced in code, and sabotaged on purpose by a mutation test that must fail when the rule is removed.

How it evolved

It began as a two-agent documentation pipeline. An improvement loop kept rebuilding it until it became a general, governed teammate. Every step below shipped as a reviewed pull request.

    What review caught

    Each batch of features got an adversarial review whose job was to break it. These are some of the real findings. Each fix shipped with a test that fails without it.

    The improvement loop

    The project is built by a loop that runs every half hour, not in one big push. Each tick ships up to five changes, and each change passes the full gate before it is committed.

    Research

    Compare against what a team would expect, and against operability needs in production.

    Build

    Small, reviewable commits, each with the eval that proves it.

    Break it

    An adversarial review tries to defeat each new feature.

    Prove the guard

    Every safety rule has a mutant that must be caught.

    Ship

    Typecheck, 500+ evals and CI, then a pull request a person merges.

    Architecture

    Files and git are the system of record. No database. An agent is configuration on the same engine: its envelope, its skills and its triggers.
